# `skillctl` 坐标解析与校验规格（coord）

## 1. 模块职责

坐标模块负责：

- 解析两种输入形式并统一为结构化坐标对象
- 做本地“格式级”校验（非法格式 → exit=2）
- 为 API 路径拼接提供可靠的编码与转义策略（避免 path 注入）

## 2. 输入形式

支持两种输入并统一为：

- 形式 A：单字符串 `group/name:version`
- 形式 B：三段式 `--group <g> --name <n> --version <v>`（或命令位置参数拆分为三段）

输出结构（概念）：

- `group: string`
- `name: string`
- `version: string`

## 3. 解析规则（形式 A）

对 `group/name:version`：

- 必须包含且仅包含一个 `/` 分隔 group 与 name（建议允许 group 内含 `.`）
- 必须包含 `:` 分隔 name 与 version
- 解析顺序建议：
  1. 找到最后一个 `:` 作为 version 分隔（避免 name 中出现 `:`；v1 建议 name 不允许 `:`，因此也可取第一个 `:`）
  2. 在 `:` 前部分找到第一个 `/`

非法示例（应判定为用法错误）：

- 缺少 `/` 或 `:`
- `group`/`name`/`version` 任一为空

## 4. 校验规则（v1）

### 4.1 `group` / `name`

必须匹配：

- `^[A-Za-z0-9_.-]+$`

与规范/需求一致：

- `docs/cli-skillctl-规范.md`
- `docs/skill-管理平台-需求文档.md`（建议规则）

### 4.2 `version`

v1 不强制 semver，仅要求非空且不包含 path 分隔风险字符：

- 建议限制为 `^[A-Za-z0-9_.+:-]+$` 或更严格（若与服务端一致）

可选增强：

- `--strict-semver`：本地严格校验 semver（“早失败”）

## 5. URL 编码与路径拼接

服务端 API path 使用 `{group}/{name}/{version}`：

- 在拼接时必须对每个 path segment 做安全编码（至少禁止 `/`、`..`、`\`、控制字符）。
- 若编码后与服务端不兼容，优先通过校验禁止这些字符；以“明确失败”替代“隐式不一致”。

## 6. 错误与退出码

- 解析/校验失败：视为用法错误，exit=2
- 非 `--json`：stderr 给出明确提示（指出哪个字段不合法、期望格式）
- `--json`：输出最小错误对象（见 `00-overview.md`）

## 7. 验收标准

- 覆盖典型边界用例：空串、缺分隔符、非法字符、超长字符串。
- 与服务端坐标规则不一致时，CLI 采取“更保守”的校验并在错误提示中指向规范约束。
